# Retail Sales Analysis (SQL + Power BI)

End-to-end analysis of a multi-table retail sales dataset — from raw transactional
data to an interactive Power BI dashboard and actionable business insights.

## What this project does

- **SQL (SQLite)**: joins across a 5-table schema (`sales`, `products`, `stores`,
  `regions`, `customers`), aggregations, and window functions (`LAG`, `RANK`,
  running totals) to surface top products, regional performance, and MoM growth.
- **Power BI**: an interactive dashboard tracking revenue, growth trends, and
  category performance, built on the flat export produced by the SQL layer.
- **Insights**: 3 business takeaways that could inform inventory and marketing
  decisions (see below).

## Dataset

Synthetic but realistic retail transactions (generated with `data/generate_data.py`,
seeded for reproducibility): 15,000 sales, 500 customers, 25 products across 5
categories, 20 stores across 5 regions, spanning Jan 2023–Dec 2024.

| Table | Description |
|---|---|
| `sales.csv` | Fact table: sale_id, date, store, product, customer, qty, discount, revenue |
| `products.csv` | product_id, name, category, unit_cost, unit_price |
| `stores.csv` | store_id, name, region_id, city |
| `regions.csv` | region_id, region_name |
| `customers.csv` | customer_id, name, email, signup_date |

## How to reproduce

```bash
# 1. Generate the dataset
cd data
python generate_data.py

# 2. Load it into a SQLite database
python -c "
import sqlite3, pandas as pd
conn = sqlite3.connect('retail_sales.db')
for t in ['regions','stores','products','customers','sales']:
    pd.read_csv(f'{t}.csv').to_sql(t, conn, if_exists='replace', index=False)
"

# 3. Run the analysis queries
sqlite3 retail_sales.db < ../sql/queries.sql
```

The flat, join-resolved export used for Power BI is in
`powerbi_exports/sales_flat_export.csv`.

## Building the Power BI dashboard

1. Open Power BI Desktop → **Get Data → Text/CSV** → load `sales_flat_export.csv`.
2. Create measures (Modeling → New Measure), e.g.:
   ```
   Total Revenue = SUM(sales_flat_export[revenue])
   Total Units = SUM(sales_flat_export[quantity])
   Avg Order Value = DIVIDE([Total Revenue], DISTINCTCOUNT(sales_flat_export[sale_id]))
   ```
3. Build visuals:
   - Line chart: `sale_date` (month) vs `Total Revenue` — trend over time
   - Bar chart: `region_name` vs `Total Revenue` — regional performance
   - Treemap or bar: `category` vs `Total Revenue` — category mix
   - Table + KPI cards for top products
   - Slicers on `region_name`, `category`, and date range
4. Save as `retail_dashboard.pbix` and add it to this repo (Power BI files aren't
   generated by this environment — build it locally with the CSV above, or a BI
   tool of your choice, then commit the `.pbix` and a screenshot).

## Key Business Insights

1. **Sports and Beauty categories drive over half of revenue (30.5% and 22.9%
   respectively)** — while Home & Kitchen lags at just 12.5% despite similar SKU
   count. Inventory and marketing spend should be reallocated toward the
   top-performing categories rather than split evenly.

2. **Regional revenue is heavily concentrated** — the West region generates ~5.8x
   the revenue of the Northeast. This points to either a genuine demand gap (worth
   a targeted regional marketing push in the Northeast) or a distribution/stocking
   gap worth investigating at the store level.

3. **Revenue is seasonal, peaking in Q4 (Nov–Dec)** with a visible dip in
   mid-year months. Inventory planning and promotional calendars should front-load
   stock ahead of the holiday season and consider mid-year promotions to smooth
   demand.
